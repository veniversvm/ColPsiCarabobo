# AI Context: internal/

## Purpose
All application business logic (Go internal package = no external imports)

## Architecture
Clean Architecture (Domain → Repository Interface → Service → Handler → Router)

## Sub-packages
- `config/` — Singleton env configuration
- `domain/` — Entity models + repository interfaces (the "contract layer")
- `handler/` — HTTP handlers (Fiber context binding, response mapping)
- `middleware/` — Security perimeter (JWT auth, rate limiting, idempotency, analytics)
- `repository/postgres/` — GORM implementations of domain interfaces
- `request_structs/` — DTOs with validator tags, multipart support, pointer-based PATCH semantics
- `router/` — Route definitions grouped by module
- `service/` — Business logic (admin, psi, posts, specialties, analytics, mail, error mapping)
- `templates/` — Embedded HTML email templates
- `utils/` — Pure utility functions (validation, sanitization, crypto)

## Dependency Flow
handler → service → repository → domain

## Key Pattern
All DB access goes through repository interfaces defined in `domain/`

## Security
Auth in middleware, validation in request_structs, business rules in service

~50+

## Modules
Admin CRUD, Psychologist Directory, Posts/CMS, Specialties, Analytics, Auth
