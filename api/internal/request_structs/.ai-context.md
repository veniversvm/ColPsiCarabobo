# AI Context: internal/request_structs/
## Purpose: DTOs — validate, sanitize, and project all incoming request data
## Architecture Role: Anti-Corruption Layer between HTTP and Business Logic
## Design Principles:
  - Pointer semantics: *string, *int for PATCH (nil=skip, empty=clear)
  - Privacy by design: Internal-only fields use json:"-"
  - Multipart support: *multipart.FileHeader for image uploads
  - Unicode safe: All text fields sanitized
## Files:
  - psi_user.go: CreatePsiUserRequest, UpdatePsiUserRequest, GetPsiUserParams
  - psi_user_Admin_requests.go: Admin-level psi user DTOs
  - request_posts.go: CreatePostRequest, UpdatePostRequest, GetPostsParams
  - specialty_requests.go: Specialty CRUD DTOs
  - social_media.go: Social media CRUD DTOs
  - response_request.go: Standardized response structs
  - requests_admin.structs.go: LoginRequest, RegisterRequest, Admin CRUD DTOs
  - directory_filter_sanitizer.go: Search filter sanitization
## Validation: validator/v10 tags (required, min, max, email, oneof)
## Used By: All handlers validate requests through these structs
