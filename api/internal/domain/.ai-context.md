# AI Context: internal/domain/
## Purpose: Entity definitions and repository interface contracts (the "contract layer")
## Architecture Role: Domain defines WHAT the system knows, NOT how to do it
## Models (16):
  - AuditModel: Base with gorm.Model + CreatedAt/UpdatedAt/DeletedAt + audit fields (CreateBy, UpdateBy, CreateById, UpdateById)
  - UserAdmin: Admin staff (UUID PK, username unique, email unique, password json:"-", key json:"-", sudo, 15+ granular permission booleans)
  - PsiUserModel: Psychologist profile — the main entity (UUID PK, username, email, password, FPV int unique, CI int unique, nationality, born_date, genre, solvents, proof_of_life, profile_picture_s3_key, contact fields, location fields for Carabobo/outside/outside-Venezuela with show_* privacy flags, primary/secondary work area, mini_bio, bio_text_id FK→TextModel)
  - PsiUserColData: Professional guild data — 1:1 with PsiUserModel (uniqueIndex on PsiUserModelID, guild_inscription_date, university_undergraduate, graduate_date, mention, 3 title S3 keys, register data, 6 guild role flags, solvency date, double guild flags)
  - PsiUserSocialNetwork: Social links — 1:N with PsiUserModel (platform name, url, is_active toggle)
  - PsiUSerSolvency: Payment records — 1:N with PsiUserModel (unique composite index on PsiUserModelID+Date)
  - PsiUserPostGrade: Postgraduate titles — 1:N with PsiUserModel (enum type: diplomado/especializacion/maestria/doctorado, title, university, graduation_year, 3 S3 keys)
  - PsiObservations: Internal admin notes — 1:N with PsiUserModel (content only, NEVER visible to psychologists)
  - PsiODeontologia: Ethics/disciplinary records — 1:N with PsiUserModel (content only, admin-only access)
  - PsiSpecialtyModel: Specialty catalog (uint32 PK not UUID, name unique index, description, active)
  - TextModel: Long content storage (UUID PK, text content) — separated for XSS filtering + query performance
  - Post: CMS posts (UUID PK, title, short_description, type=public|psi, text_id FK→TextModel, image_s3_key, status enum: draft/published/archived/scheduled, publish_at for scheduled)
  - LoginEvent: Auth analytics (uuid PK, user_id, username, role psi|admin, ip, user_agent)
  - PageView: Route visit tracking (uint auto PK, path, method, user_id nullable, session_id, ip, referer)
  - SearchEvent: Directory search tracking (uint auto PK, query, specialty, municipality, state, results_count)
  - ProfileView: Profile visit tracking (uint auto PK, psi_id, viewer_id nullable, session_id)
  - ActiveSession: Live session tracking (uuid PK, unique index on user_id, username, role, ip, last_seen, expires_at) — has IsActive() method
## Relationships: PsiUserModel → ColData (1:1), → SocialNetworks (1:N), → PostGrades (1:N), → Solvencies (1:N), → Observations (1:N), → Deontologia (1:N), → TextModel via BioTextID (N:1). Post → TextModel (1:1).
## Interfaces: PsiUserRepository (30+ methods: CRUD, search/directory, postgrades, solvencies, social networks, sitemap), PostRepository (CRUD, list with PostFilter, PublishScheduled, sitemap), UserAdminRepository (CRUD, GetByIdentifier, CountSudos), SpecialtyRepository (CRUD with soft-delete, GetAllAdmin)
## Key Pattern: All interfaces use context.Context as first param, return error as last return value
## Visibility Pattern: PsiUserModel has show_* boolean flags per sensitive field — handlers filter output based on these for public vs admin views
## Used By: Every layer in the system depends on domain — service layer imports interfaces, infrastructure implements them
## DB Tables (from migration): 16 tables total with UNIQUE constraints on CI, email, username, FPV, composite (PsiUserModelID+Date) for solvency
## File Mapping: audit.model.go, user.model.go (UserAdmin+PsiUserModel+ColData+Solvency+PostGrade+Observations+Deontologia), psi_specialty.model.go, social_media.model.go, text.model.go (TextModel+Post+PostStatus), analytics.go (5 analytics models)
